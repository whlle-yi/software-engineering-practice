# 选题要求（摘自任务书）

> **来源**：`模板及总体要求\0-大作业任务书\0-大作业任务书.md` §一/§二/§五/§六/§七（只读）。
> 本文件是选题讨论的工作依据，定稿后本工作区的产物以此为标尺。

## 一、选题来源（三选一）

1. **从 10 个参考选题中任选一题**：本地网络工作站流量检测、网络工作站监视、软件工程教学演示系统、客户信息服务网络系统/网络客户服务中心、短信网络预定服务、网络/手机娱乐与游戏软件、毕业生信息服务网络系统、手机炒股软件、微型 DBMS 系统（原文见任务书 §一）。
2. **参考历年创新创业活动选题**，结合兴趣和技术发展潮流自定。
3. **特别鼓励**：从学习、生活实践中提出新选题。

> 注：10 个参考题语境偏老（短信、手机炒股），选它们不扣分但难有创新性加分；自选新题更易占优。

## 二、硬性约束

- **3–5 人一组**（已组队，人数姓名待填：见 `1-可行性研究报告工作区\小组分工表-v0.1.md`），课外完成。
- **时间**：第 1–2 周（现在）定选题；第 3–4 周即开始搜集资料做可行性分析——选题必须具体到能立刻调研。

## 三、筛选标准：选题要扛得住后面 16 周

| 后续环节 | 对选题的要求 |
| --- | --- |
| 可行性报告（15 分） | 问题定义明确——面向谁、解决什么痛点、**数据从哪来**能回答 |
| 需求分析（15 分） | 画得出 DFD、UML 用例/类图，编得出数据字典——业务流程不能太薄 |
| 系统设计（30 分，分值最重） | 有像样的模块划分、界面、**算法**（评分明确看"算法的先进性"）——纯增删改查吃亏 |
| 原型开发（12–13 周） | 16 周内做得出原型或核心功能——体量可控，避开要爬海量数据/对接付费接口的题 |
| 演示答辩（14–15 周） | 能现场跑起来演示 |

**一句话**：好选题 = 有真实场景和数据来源 + 业务流程够画 2~3 张 DFD + 有一个拿得出手的核心算法 + 4 周内能出原型。

## 四、定稿动作

1. 选题结论记入本工作区（如 `选题结论.md`），写明题目、面向对象、痛点、数据来源、核心算法设想。
2. 回填 `1-可行性研究报告工作区\可行性研究报告-v0.1.md` 的封面与 1.2 背景。
3. 同步课程根 `README.md` 进度表（选题状态改为已定）。
