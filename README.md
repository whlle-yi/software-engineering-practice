## 三、五条硬性规则

> 完整版见 `AGENT.md`，这里只列最容易出错的五条。

1. **模板只读**：`模板及总体要求\` 里的文件不改名、不改内容、不覆盖。要加工就复制副本到 `第N次\` 下再改。
2. **双格式交付**：每份文档必须同时产出 `.md` 和 `.docx`，同目录并列。md 是唯一手改版本，docx 由 md 生成，不单独编辑。
3. **格式铁律**：老师模板的样式、字号、行距、页边距、分节页码一律不改；填的内容必须套模板已有样式。参数见 `第一次\要求\1-模板排版规格.md`。
4. **归属看适用范围**：约束全部阶段的（任务书）→ 只读区；只约束本次的格式要求 → `第N次\要求\`；本次产物 → `第N次\1-XXX\`。
5. **不预建空目录、同一份文件只存一份**：到哪一步建哪一步；原件不复制到提交目录。

## 六、技术备忘与坑

- **git 仓库在课程根**（`.git` 与 `AGENT.md` 同级），一个仓库覆盖全部提交目录与 `项目本体\`。2026-10-20 之前 `.git` 误放在 `第一次\` 下，已上移。
- **不入库的三类**：`模板及总体要求\`（老师原件）、`Mermaid 结构化分析图表练习\`、`.workbuddy\`。克隆后需自备模板原件。
- **生成 Office 文档必须用系统 python**（`C:\Users\32530\AppData\Local\Microsoft\WindowsApps\python.exe`），它才有 `python-docx` 和 `pywin32`；托管 python 没装。
- **本机没有 MS Project**，项目计划用 Excel 甘特图等价实现，表内已注明。
- **模板目录是真 TOC 域**，页码可自动更新；但 Word 更新时会另建 `toc N` 样式顶掉"目录 1/2/3"，`md2docx.py` 已处理。
- **二级标题用黑体、三级标题回到宋体**，是模板原样，不要"统一"。
- **模板里的指导语（"说明……"）必须删除替换**，这是最容易犯的错。
- **WPS 后台进程会独占文档**，导致文件无法移动或删除，需完全退出 WPS 再操作。
- **`git add -A` 会把未跟踪文件一并纳入**，误加后需 `git rm --cached`。`.gitignore` 已忽略整个 `.workbuddy/`。
