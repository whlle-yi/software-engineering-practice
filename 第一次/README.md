## 交付规格

**每阶段产出两份文件，格式不同、用途不同，缺一不可。**

| 文件 | 用途 | 由谁维护 |
| --- | --- | --- |
| `XXX-v1.0.md` | **源文件**。手工维护，供下一阶段读取交接 | 我 |
| `XXX-v1.0.docx` | **提交件**。交给老师，内容与 md 一致 | 由 md 生成 |

- **md 是唯一手改版本**，docx 从 md 导出，不单独编辑——否则两个版本必然分叉。
- **交接靠 md**：第 2 阶段写需求规格说明书时，以第 1 阶段的 `可行性研究报告-v1.0.md` 为输入（项目背景、目标、约束、备选方案都从这里继承），不必再去翻 Word。
- 下一阶段文档开头写明继承了上一阶段的哪个版本，便于追溯。

### 格式铁律

老师模板里的样式、字号、行距、页边距、分节与页码规则**一律不改**，自己填的内容必须套用模板已有样式，不能手动改字体"看着差不多"。

完整参数见 `要求/1-模板排版规格.md`（从模板逐项解析得出，非目测）。三条最容易踩的：

1. 模板里的指导语（"说明编写本报告的目的……"）必须删掉，不是留着当正文
2. 二级标题用黑体、三级标题回到宋体，这是模板原样，不要"顺手统一"
3. 模板目录是静态文字，页码不会自动更新，正文定稿后必须重算回写

## 约定

**归属看适用范围，不看产生时间**：一份文件放在哪层，由它**约束几个阶段**决定，不由"什么时候产生的"决定。
- 约束全部 5 个阶段的（任务书）→ `模板及总体要求\0-大作业任务书\`
- 约束某一个阶段的（模板、模板转录件）→ `模板及总体要求\` 下对应编号夹，如 `1-可行性研究报告模板\`
- 只约束本次的格式要求（排版规格）→ `第N次\要求\`
- 是本次的产物（报告、计划、分工表）→ `第N次\1-可行性研究\`

**课程要求一编号一文件夹**：`0`~`5` 各一个文件夹，统一收在 `模板及总体要求\` 下，内含该编号的 Word 原件与 md 转录件，原件名一字不改。

**模板只读**：`模板及总体要求\` 里的文件一律不直接修改，要加工就复制副本到本次提交目录再改。详见课程根 `AGENT.md`。

**原件不复制**：提交目录不再复制 Word 副本，也不重复存放模板转录件。同一份文件存在两处，早晚会改错版本。

**编号与课程一致**：目录序号沿用老师资料编号（0 任务书、1 可行性、2 需求…），不另造编号体系。

**到哪一步建哪一步**：不预建空目录。`第二次\`、`项目本体\src\` 等在真正开始对应工作时才创建。

**文档带版本**：`名称-v主.次.md`，`0.x` 内部迭代、`1.0` 起对外。同一文档只留一份，历史由 git 记录。

**项目本体独立**：项目横跨三个阶段，不属于任何一次提交，因此与 `第N次\` 平级置于课程根下，将来单独建版本库。
