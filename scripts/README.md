# scripts\ · 项目脚本

> 代码聚集地，**扁平放置**：一个脚本一个文件，不做子目录层级。

## 命名规则

脚本服务于哪个交付物，**必须体现在文件名里**，格式：`<功能>_<交付物英文名>.py`。
交付物英文名对照（后续报告沿用，不另造）：

| 编号 | 交付物 | 英文名 |
| --- | --- | --- |
| 1 | 可行性研究报告 | `feasibility` |
| 2 | 需求规格说明书 | `srs` |
| 3 | 概要设计说明书 | `hld` |
| 4 | 详细设计说明书 | `lld` |
| 5 | 测试计划 | `test` |

例：需求阶段的分析脚本叫 `md2docx_srs.py`；跨交付物共用的脚本不带后缀（如未来的 `md2docx_common.py`）。

## 现有脚本

| 文件 | 用途 | 绑定 |
| --- | --- | --- |
| `md2docx_feasibility.py`（v2） | md → docx 生成器：在模板副本上加工（段落克隆保格式零漂移）+ 封面填空 + TOC 更新 | **1 号模板**：封面槽位表、"正文从第 76 段开始"、原型段识别句三处专用；直接喂其他模板会填错封面 |

## 使用

```bash
# 生成提交件（必须用系统 python，托管 python 没有 python-docx）
# 模板副本默认取 .workbuddy/tools/可行性报告模板.docx，可在任意工作目录下运行
"$HOME/AppData/Local/Microsoft/WindowsApps/python.exe" \
  scripts/md2docx_feasibility.py 1-可行性研究报告工作区/可行性研究报告-v1.0.md \
                                 1-可行性研究报告工作区/可行性研究报告-v1.0.docx
```

md 书写契约见 `md2docx_feasibility.py` 头部 docstring，**必须遵守**（必须有 `## 封面` 节、封面未知字段留空、行内只用 `**粗**`/`*斜*`、图片独立成行等）。

## 其他报告接入计划

2~5 号报告格式各异：到各阶段开工时，先从对应模板复制副本并实测其封面/正文结构，再新增脚本
（复制现有脚本改配置，或抽公共模块后写薄入口——到时按实际差异决定，原则是**每份实现只有一处生效**）。
