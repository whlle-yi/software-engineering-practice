## 三、五条硬性规则

> 完整版见 `AGENTS.md`，这里只列最容易出错的五条。

1. **模板只读**：`模板及总体要求\` 里的文件不改名、不改内容、不覆盖。要加工就复制副本到对应 `X-XXX工作区\` 再改。
2. **docx 单文件直改直登记**（2026-10-31 起，替代原「双格式交付」）：docx 是唯一工作文件，改动直接在 docx 上进行，每处手工修改登记入工作区 README；不再维护 md 正本（`md2docx` 生成链保留备用）。
3. **格式铁律**：老师模板的样式、字号、行距、页边距、分节页码一律不改；填的内容必须套模板已有样式。
4. **归属看适用范围**：约束全部阶段的（任务书）→ 只读区；只约束本交付物的格式要求 → `X-XXX工作区\要求\`；本交付物产物 → `X-XXX工作区\` 根。
5. **工作区已预建、文件到步再建**：0~5 六个工作区已建好（各含 README）；工作区内的文件到对应阶段才产生；同一份文件只存一份，原件不复制到工作区。

## 四、技术备忘与坑

- **git 仓库在课程根**（`.git` 与 `AGENTS.md` 同级），一个仓库覆盖全部提交目录与 `项目本体\`。2026-10-20 之前 `.git` 误放在 `第一次\` 下，已上移。
- **不入库的三类**：`模板及总体要求\`（老师原件）、`Mermaid 结构化分析图表练习\`、`.workbuddy\`。克隆后需自备模板原件。
- **生成 Office 文档必须用系统 python**（`C:\Users\32530\AppData\Local\Microsoft\WindowsApps\python.exe`），它才有 `python-docx` 和 `pywin32`；托管 python 没装。
- **交付件的 COM 操作（更新目录、导 PDF 等）一律用 WPS**（`KWPS.Application`，DispatchEx 独立实例），**禁用 Word.Application**——本机装有真 Word，但用户工作流在 WPS，两者保存链不同；WPS 忙时会逐调用拒绝，须每个 COM 调用单独退避重试。孤儿进程（隐藏窗口）会锁文件，taskkill 后解锁。
- **WPS 保存链会劣化图形**：svgBlip 被剥、EMF 转位图、图片降采样——插图一律用 600dpi PNG 注入，终稿从 docx 直接导 PDF，勿以 WPS 再次保存的版本为准。
- **模板目录是真 TOC 域**，页码可自动更新；但重建目录会打乱条目样式，更新后须把条目样式改回模板的目录样式（各模板样式名实测见各工作区 `要求\`）。
- **二级标题用黑体、三级标题回到宋体**，是模板原样，不要"统一"。
- **模板里的指导语（"说明……"）必须删除替换**，这是最容易犯的错。
- **WPS 后台进程会独占文档**，导致文件无法移动或删除，需完全退出 WPS 再操作。
- **`git add -A` 会把未跟踪文件一并纳入**，误加后需 `git rm --cached`。`.gitignore` 已忽略整个 `.workbuddy/`。
