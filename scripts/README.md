# scripts\ · 项目脚本目录

> 每个**交付物一个脚本子目录**（目录名 = `编号-交付物名`，与工作区对应），该报告专属的生成/处理脚本放各自目录；
> 跨报告共用的机制放 `common\`。目录到对应阶段开工时才建，不预建。

## 现状

| 目录 | 内容 | 说明 |
| --- | --- | --- |
| `1-可行性研究报告\` | `md2docx.py`（v2） | md → docx 生成器，**绑定 1 号模板**：封面槽位表、"正文从第 76 段开始"、原型段识别句均为 1 号模板专用 |
| `common\` | （空，暂无独立模块） | 公共机制现阶段**内联在 1 号脚本里**；参数化改造时抽出为共享模块 |

## 已定的演化计划

直接给 2~5 号报告换模板会填错封面、删错正文（三处绑定点）。**第 7–9 周需求阶段开工时**做参数化改造：

1. 从 1 号脚本抽出公共核心（模板副本加工、段落克隆、封面槽位机制、TOC 更新、样式还原）→ `common\`；
2. 每报告目录只留一份**配置**（模板副本路径、封面槽位表、正文起点、原型段识别句）+ 薄入口脚本；
3. 为 2 号模板建 `2-需求规格说明书\`，用模板副本实测封面槽位后填配置。

## 使用

```bash
# 生成提交件（必须用系统 python，托管 python 没有 python-docx）
# 模板副本默认取 .workbuddy/tools/可行性报告模板.docx，可在任意工作目录下运行
"$HOME/AppData/Local/Microsoft/WindowsApps/python.exe" \
  scripts/1-可行性研究报告/md2docx.py 1-可行性研究报告工作区/可行性研究报告-v1.0.md \
                                      1-可行性研究报告工作区/可行性研究报告-v1.0.docx
```

md 书写契约见 `1-可行性研究报告/md2docx.py` 头部 docstring，**必须遵守**。
