# 小组分工表

> 课程要求 3–5 人一组。分工不是"挂名"，评分会看成员协作与项目安排，因此每个阶段都要有明确主责人。
> 用法：填完成员表，再在责任矩阵里标出各阶段的主责（●）与参与（○）。

## 一、成员

| 编号 | 姓名 | 学号 | 角色 | 主要职责 | 联系方式 |
| --- | --- | --- | --- | --- | --- |
| 1 | | | 组长 | 统筹进度、评审答辩主讲、对外沟通 | |
| 2 | | | 需求分析 | 需求调查、DFD/数据字典、需求规格说明书 | |
| 3 | | | 系统设计 | 体系结构、模块划分、数据库设计 | |
| 4 | | | 开发实现 | 原型开发、核心功能编码、编码规范 | |
| 5 | | | 测试与文档 | 测试计划与用例、文档排版与归档 | |

> 4 人组可合并"测试与文档"到需求分析或开发；3 人组至少保证需求、设计、实现各有一人主责。

## 二、角色职责

| 角色 | 负责产出 | 关键节点 |
| --- | --- | --- |
| 组长 | 项目计划、进度跟踪、答辩主讲 | 第 2 周定选题、第 4 周交可行性报告、第 15 周答辩 |
| 需求分析 | 需求规格说明书（含 DFD、数据字典、用例） | 第 7–9 周 |
| 系统设计 | 概要设计、详细设计、数据库设计 | 第 10–11 周 |
| 开发实现 | 原型、核心功能代码、编码规范 | 第 12–13 周 |
| 测试与文档 | 测试计划、测试用例、文档排版与版本管理 | 第 12–13 周，全程排版 |

## 四、协作约定

| 项 | 约定 |
| --- | --- |
| 版本管理 | 文档用 git 管理，`main` 保持可提交状态，个人改动走分支后合并 |
| 文件交接 | 文档以 `.md` 交接，`.docx` 由 md 导出，不直接在 Word 里改 |
| 评审互查 | 每次提交前组内交叉检查一遍（写的人不查自己那章） |
| 会议 | 每周一次短会，结论直接落到当次文档的修订记录里，不单独建会议纪要文件 |
| 冲突处理 | 进度落后时优先保"能交付的最小完整版本"，不追求单章完美 |
